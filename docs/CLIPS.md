# Narrated clips

A clip is a short animated, narrated story (45 to 75 seconds, 90 at most) made from the same scenes as a lesson explainer, rendered to an mp4 plus a poster. Part of `docs/superpowers/specs/2026-11-06-course-expansion-design.md`, Phase 2.

## How it fits together

- `content/clips/<slug>.json` is the **spec**: `{ title, backdrop?, subject?, scenes }`. Scenes use the explainer scene format (items sharing an `id` glide, `camera`, `effect`, and so on) and each needs a `say` script. At least 80% of scenes must have `say`; up to 24 scenes; the estimate (narration at 2.3 words a second, 0.5 s after each scene, two 1.5 s cards) must be 90 s or less. Validation is `clipSpecSchema` in `packages/schema/src/clip.ts`.
- The files are named from the spec: `clip-<lesson-slug>-<first 8 hex of sha256 of the canonical spec>.mp4`, and the same with `.webp` for the poster. Change the spec and the names change; leave it alone and nothing is ever re-rendered or renamed.
- `apps/web/src/components/ExplainerStage.tsx` draws the picture for both the lesson player and the video, so the clip looks exactly like the lesson animation.

## Authoring

In a topic file, pass `clip` to `topicLesson`:

```js
topicLesson({ /* ...as before... */, clip: { title: "Sharing a pizza", backdrop: "kitchen", scenes: [ /* ... */ ], caption: "Watch Pip share a pizza." } })
```

`node scripts/build-topics.mjs` then adds a "Movie time" stop (a heading and the `clip` block) to the `learn` part just before its summary, and writes the spec to `content/clips/<slug>.json`. Seconds and transcript are worked out from the scenes. See `content/clips/sample-halves.json` for a complete example. Keep sentences short (the lesson audit limits them by age band).

## Rendering, step by step

One-time setup: `cd tools/clips && npm install` (Remotion 4.0.541 and Tailwind; downloads a headless Chrome on first render).

1. **Try it without a voice** (works offline, no secrets):
   `node scripts/render-clip.mjs content/clips/sample-halves.json --silent`
   Output goes to `tools/clips/out/silent/`. Scenes last as long as the narration would at reading pace, captions are burned in, there is no sound, and the media manifest is not touched.
2. **Narration** needs the live app: set `LMS_URL`, `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET` (the same service token as `scripts/import-lessons.mjs`, see `docs/SERVICE_TOKEN.md`).
   `node scripts/clip-audio.mjs <slug>` asks the app to voice each sentence (`POST /api/admin/voice/prewarm`, batches of 100), downloads each sentence's mp3 (`GET /api/admin/voice/audio`) into `tools/clips/.audio/`, and measures it. The sentence splitter is the shared `sentences()` in `@lms/schema`, so the audio is the same cache the children's app uses.
3. **Render**: `node scripts/render-clip.mjs <slug>` (runs step 2 first if needed). Renders H.264 + AAC at 1280x768, 24 fps; if the file is over 8 MB it retries at stronger compression and fails clearly if it never fits. The poster is a frame at 35% of the video. Both files land in `tools/clips/out/` with their deterministic names, their sha256 goes into `content/media/manifest.json` (`source: "generated"`, `reviewed: false`, only when `content/topics/<slug>.json` exists), and the exact upload command is printed:
   `node scripts/upload-media.mjs tools/clips/out/clip-<slug>-<hash>.mp4 tools/clips/out/clip-<slug>-<hash>.webp`
4. **Review**: watch the clip, then set `reviewed` to `true` in the manifest before uploading.
5. **Batch**: `node scripts/render-clip.mjs --all` renders every spec in `content/clips/` (except `sample-*`) whose output is missing. It is resumable: files that already exist are skipped. `--force` re-renders one.

Look at single frames with `node tools/clips/scripts/frame.mjs <slug> 100 900 100` (png files in `tools/clips/out/frames/`, sha256 printed; the same frame twice gives the same hash).

## The daily voice budget

Narration is generated by the app's own voice service and counts against the **daily AI ceiling** (an admin Settings value, `aiDailyCap`). About 25,000 characters a day is the planned ceiling; one clip is roughly 700 to 900 characters. If the budget runs out part way, `clip-audio.mjs` / `render-clip.mjs` stop with exit code 3 and say how many sentences remain. Sentences already voiced are kept (and are free next time), so just **run the same command again after 00:00 UTC**. Prewarm lessons' own narration at the same time of day. See `docs/PHASE1_SPIKES.md`, part 4, for the owner's budget decision (the free allowance is lower than the ceiling, so it needs the paid plan first).

## How frames are made repeatable

Chromium runs CSS animations on its own clock, so a plain screenshot would differ every time. For each video frame the composition (`tools/clips/src/ClipStage.tsx`) mounts the stage fresh, draws step 0, forces a style recalculation, notes which animations began, draws step 1, and so on up to the scene on screen. That makes the CSS transitions that depend on the previous step (things gliding between places) exist exactly as they do for a child. Then every animation is paused at *(now minus the start of the scene it was born in)* and the frame is held until they have all settled (`tools/clips/src/seek.ts`, the technique proven in `docs/PHASE1_SPIKES.md`). A `CountUp` number reads the same clock instead of `setInterval`.

Limits: Remotion is free for individuals and very small teams; confirm it fits before wider use. Fonts are the system fonts of the machine that renders.
